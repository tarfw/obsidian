# Taste
- Wants status/plan-vs-implementation comparisons presented as a markdown table (explicitly asked "...stage of implementation... in table"), e.g., columns like stage | planned files | actual status. Confidence: 0.8
- Impatient with slow progress — asked "what happen. why taking so long" when a heavyweight exploration subagent stalled (500k+ tokens, no output). Expects the agent to avoid slow approaches (prefer direct file reads/greps over large subagent delegations when feasible) and to briefly explain delays, then pivot fast. Confidence: 0.6
- Prefers plan-first for non-trivial changes: explicitly asks for an implementation plan before touching code ("give me the plan to implement..." for swapping the site agent in tarapp), rather than immediate edits. Plan should be grounded in exploration of both sides (current wiring + target API surface). Confidence: 0.7
- For bug reports, wants direct diagnose-and-fix with no plan round-trip ("find th eissue and fix" for the unstyled published site) — agent should fetch the live output, trace root cause through the pipeline, and fix it autonomously; plan-first applies to feature-level changes, not bug fixes. Confidence: 0.6
- Tests on a physical Android device using an Expo development build (internal-testing APK), not an emulator or Expo Go. The user runs everything on-device manually themselves: they launch the dev client on the phone AND run `npx expo start` (Metro bundler) in their own terminal. Never start Metro as a background task or run adb/device-launch flows — just tell them when it's time to run it. Confidence: 0.85
- When verifying fixes to the live site worker (siteagentv2): run `npm run typecheck && npm test` first, deploy with `npx wrangler deploy`, then smoke-test end-to-end via the `/draft` endpoint on a throwaway subdomain so the live site's KV keys are never touched; clean up test artifacts afterward. Confidence: 0.5
- When abandoning a failed iteration/experiment, wants a complete clean removal of all its traces before starting something new ("remove the @siteagentv2 clean... i am planning new"): delete the untracked project folder, remove committed design docs, revert all related code changes to the pre-experiment state, delete new untracked files, and verify no dangling references remain. Picks the full-removal option over partial cleanups. Confidence: 0.7
- LLM calls must use only `qwen/qwen3.6-27b` via the Groq API (`https://api.groq.com/openai/v1/chat/completions`) — user explicitly mandated "i want only this model to be used in ours" when the worker was calling `groq/compound-mini`; applied at every LLM call site (llm-client.ts, patch-generator.ts). Note: this model emits `<think>...</think>` reasoning blocks that must be stripped from responses before JSON parsing. Confidence: 0.9
- Prefers short, concise explanations: when asking how something works ("how siteagent works in @taragent... tell me short"), wants a tight overview — key components, dispatch flow, and pipeline stages — not a verbose code walkthrough. Confidence: 0.5
- Runs on Windows PowerShell and works inside the **Zed editor's integrated terminal panel** (`TERM_PROGRAM: zed`), not a standalone terminal. Full-screen TUI apps (like a TUI CLI) exit silently there; prefer headless/non-interactive invocation (e.g. `opencode run "..."`) or tell the user to run the TUI in a standalone terminal (e.g. `wt <cmd>` / Windows Terminal) rather than expecting the TUI to render in the editor panel. Confidence: 0.6
- When asked to remove/uninstall software from the PC, wants a *clean* removal ("cleanly remove brave browser"): not just running the uninstaller, but also deleting leftover install/updater folders, user profile data, and registry keys, and verifying no traces remain (folders, uninstall entries, appx packages, scheduled tasks) before reporting done. Expects the official silent uninstaller to be used first (e.g. `setup.exe --uninstall --force-uninstall`) and elevation via UAC for protected locations. Confidence: 0.6

User typically provides the official site URL as the reference for what the tool is. Confidence: 0.5

Do not ask which files to include or pause to confirm scope. Confidence: 0.6
- Multi-line heredocs (`git commit -F - <<'EOF'`) fail in this Windows shell — when committing with a long message, write the message to a temp file and use `git commit -F <file>` instead. Confidence: 0.6
