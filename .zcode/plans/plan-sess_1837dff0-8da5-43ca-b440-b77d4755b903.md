# Fix design-token compliance in the taragent site agent

## Root cause (why sites ignore design tokens)

The gen-3 pipeline (`taragent/src/site/`) inlines each design's `:root` verbatim and hopes the LLM uses `var(--token)`. Three gaps break this:

1. **The deterministic shell uses invented token names.** `assemble.ts:73,102,127` references `--color-canvas-white` (exists in 1/25 design files), `--font-body` (0/25), `--color-ink-black` (6/25). The header/footer/body always render with hardcoded generic black/white fallbacks instead of the brand palette.
2. **Fonts never load.** `extractFontFamilies` (`assemble.ts:28-44`) puts fictional brand fonts ("Seed Sans") into the Google Fonts URL — the whole request 400s, no font loads, and the real substitutes (Inter, etc.) are dropped. Also a parsing bug: splitting on commas inside parenthetical weight lists.
3. **Lint never enforces tokens.** Shell CSS is never linted; sections may use literal hexes; `var(--typo)` references are never checked to exist.

The missing piece is the token **normalization layer** the old archived tarsite had (`compileCssVars()`) — dropped in the gen-3 rewrite.

## Approach: fresh token layer inside taragent (not a separate worker)

Rebuild token application from scratch as a new module inside `taragent/src/site/`, delete the broken logic. Staying inside taragent keeps the job/checkpoint runner, Turso/S3/KV bindings, REST routes, and single deploy — a second worker would duplicate all of that without fixing anything about tokens (this matches siteagent3.md §2). If you later want a separate worker, this layer extracts cleanly since it becomes pure functions over `designMd`.

## Changes

### 1. NEW `taragent/src/site/tokens.ts` — the token compiler (core of the fix)
Pure functions, no LLM, no network:
- `parseDesignTokens(designMd)` parses the structured sections all 25 designmds share:
  - `## Tokens — Colors` table (`| Name | Value | Token | Role |`) → token → {hex, role}
  - `## Tokens — Typography` → brand families (`### Family — …`), `**Substitute:**` lines (with the parenthetical/comma parsing bug fixed), type-scale tokens
  - `## Tokens — Spacing & Shapes` → spacing/radius tokens
- `compileUniversalTokens(tokens)` emits a small `:root` alias block appended **after** the design's verbatim `:root`, mapping role-resolved universal names to the design's real tokens:
  `--color-canvas`, `--color-ink`, `--color-accent`, `--color-border`, `--color-surface`, `--font-body`, `--font-heading`, `--radius-shell`, `--text-body`, `--text-caption` — each defined via `var(--designs-own-token, <resolved literal>)` so it always resolves.
- `buildFontPlan(tokens)` returns: Google Fonts families (substitutes only — they exist precisely because they're loadable; brand names stay in CSS stacks as first choice), plus font stacks like `--font-body: var(--font-seed-sans), 'Inter', sans-serif`.
- `tokenIndex(designMd)` → Set of all valid custom-property names (design's own + universal aliases) for lint.

### 2. REWRITE shell in `taragent/src/site/assemble.ts`
- Header/footer/`BASE_CSS` use only universal token names (now guaranteed to resolve) — no more invented names, no hardcoded `#080808`/`#fff` chrome; dark/mixed themes derive from the design's own surface tokens instead of ternary-swapped literals.
- `googleFontsLink` built from the font plan; one runtime fetch per job validates the css2 URL (cached per styleId in a module Map) and degrades to unweighted `family=X` requests if a weighted request 400s — no more all-or-nothing font failure.

### 3. TIGHTEN `taragent/src/site/verify.ts`
- Sections (strict mode): color and font-family values must be `var(--token)` (plus `transparent`/`currentColor`/`inherit`); referenced tokens must exist in `tokenIndex` — unknown var() or literal hex fails lint → repair → fallback.
- Add a final assembled-page lint pass over shell CSS (shell is token-derived by construction, this closes the loop).

### 4. UPDATE `taragent/src/site/synth.ts` + `job.ts`
- `SYNTH_SYSTEM_TEMPLATE` gains the compiled universal-token block and an explicit "colors/fonts via var() only" rule.
- `runJob` compiles tokens once per job and passes them to synth/verify/assemble (small signature changes only; checkpoint flow untouched).
- `fallbackSection()` rewritten to use universal tokens so even failed sections stay on-brand.

### 5. NEW soak test `taragent/scripts/test-tokens.mjs`
Runs the compiler over all 25 embedded seed designs and asserts: every universal token resolves for all 25, font link builds with Google-available families, no lint regressions. Also renders one full page via `buildPageHtml` to a fixture file for eyeballing, like the existing `scripts/cafe.html`.

## Verification
- `node taragent/scripts/test-tokens.mjs` — all 25 designs pass token resolution; coverage table printed.
- `npx tsc --noEmit` in taragent for typecheck.
- Fixture HTML inspection: shell CSS shows resolved brand values (e.g. Seed's footer becomes Forest Depths `#1c3a13`, not `#080808`), fonts request Inter (200), not "Seed Sans" (400).
- Live regen of one draft site is left to you after deploy (`POST /site/generate`).

## Out of scope (noted, not doing)
- Workspace `DESIGN.md` integration into site generation (separate feature; today sites are styled by the platform style library only).
- `tarapp/src/components/site.tsx` picker accent-hex mismatches (cosmetic).
- Splitting into a separate worker.
