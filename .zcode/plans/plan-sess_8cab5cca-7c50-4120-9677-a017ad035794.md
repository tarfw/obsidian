## Doc contents

**§0 Lessons from v3.1** — the seven structural gaps: no facts layer (copy duplication), per-section component drift (below Webflow/Framer grade), ~20KB design.md × 15-25 calls (LLM waste), library-only styles, edit-only UX (users can't define structure pre-generation), no asset planning, duplicated taragent/siteagent pipelines.

**§1 One-page pipeline** — 7 stages: FACTS → MATCH → PLAN → SYNTH → VERIFY → ASSEMBLE → PUBLISH, with the three principles (LLM writes HTML but never components/shell/JS; everything deterministic stays deterministic; failures contained and on-brand).

**§2 Where it lives** — siteagent worker bindings + extended API: existing routes plus `GET/PUT /site/facts`, `POST /site/plan` (plan editor), `POST /site/assets` (uploads).

**§3 Stage detail**:
1. **Business Fact Sheet** — one cheap call extracts a structured, versioned schema (identity, audience, voice, offerings[] w/ prices, USPs, proof, logistics); user-editable in studio; change requests = structured diffs, never appended prose (fixes description-compounding); `facts_version` bumps stale dependent renders.
2. **Site Plan + review gate** — job pauses in `awaiting_review` after planning; studio shows editable plan (add/reorder/delete sections, kind library + free-text custom sections, inline copy edits); chat flow auto-continues.
3. **Content-addressed render cache** — `render_key = sha256(style_id + facts_version + section brief + prompt_version)`; edit one section → one new key; restyle reuses plan/facts.
4. **Component compiler** — design.md Components → canonical `.c-btn/.c-card/.c-badge/.c-input/.c-nav` classes compiled once per style at ingest (deterministic extraction, one-time LLM assist), emitted in shell; lint forbids hand-rolled primitives; sections write layout CSS only.
5. **LLM efficiency** — ~3-4KB design digest for non-anchor sections (verbatim only for each page's rhythm anchor), batching of simple kinds, parallel synthesis (pool of 3, waitUntil), stable cache-friendly system prefix; target 11-15 calls and ~60-70% fewer input tokens vs today.
6. **Design on-ramps** — library / brand-kit→design.md / reference URL or screenshot→design.md / direct upload, all through the same validation gate + soak test.
7. **Assets** — manifest (slot, subject, aspect, alt) at plan time; resolution ladder: R2 upload → deterministic on-brand SVG from tokens; zero CLS; studio assets screen.
8. **Fact slices** — deterministic per-kind fact slicing into section prompts + "never invent/contradict facts" rule; plan-level duplicate-kind lint.

**§4-5** — checkpointed runner states (incl. review gate), edit/restyle semantics via render keys.

**§6** — provider (INFERX unchanged) + before/after cost & latency budget table.

**§7 Soak test** — additions: component compiler over 25 designs, asset SVGs on-token, digest fidelity spot-checks, facts-slice fixtures.

**§8 Consolidation** — delete `taragent/src/site/`, chat actions proxy to siteagent (service binding), shared `SITE_CACHE` KV namespace bound in both workers for serving, siteagent `/api/*` forms forward to taragent handlers.

**§9 Rollout** — ① facts + plan editor → ② component compiler → ③ digest + parallel synth → ④ assets → ⑤ design on-ramps → ⑥ consolidation; each phase ships independently.

**§10 Acceptance criteria** — measurable: zero fallback sections, zero lint violations at publish, ≤90s generate, ≤$0.02/site, single published state per workspace, custom brand-kit style passes soak.
